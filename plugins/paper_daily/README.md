# 论文日报插件

## 简介

自动从 ArXiv 获取最新论文，使用 Gemini AI 根据用户配置的研究兴趣进行智能筛选，生成中文摘要并自动打标签，以飞书卡片形式推送。支持手动触发和每日定时推送。

## 核心特性

- **智能筛选**：使用 Gemini AI 根据自然语言描述的研究兴趣判断论文相关性
- **批量处理**：每批 10 篇论文同时筛选，大幅减少 API 调用次数（约 10 倍优化）
- **中文摘要**：对推荐论文自动生成 150 字以内的中文摘要
- **自动标签**：摘要生成后统一调用 LLM 为推荐论文打标签，标签词表跨天复用，持续积累
- **断点续跑**：按日期缓存筛选、摘要和标签结果，重复运行时自动跳过已处理的论文
- **定时推送**：支持每日定时向订阅用户推送论文日报（周末自动跳过）
- **进度反馈**：实时更新飞书卡片，展示获取、筛选、摘要生成、标签归类进度
- **研究兴趣在线编辑**：支持在飞书中直接修改研究兴趣，无需重启服务
- **历史回溯**：支持通过独立脚本回溯获取指定日期的论文日报

## 触发方式

### 手动触发

在飞书聊天中发送关键词 `论文日报` 进入插件菜单，可选择：
- **获取今日日报**：立即执行完整流水线（获取 → 筛选 → 摘要 → 标签 → 推送）
- **订阅每日推送**：订阅后每天定时自动推送
- **取消订阅**：取消定时推送
- **修改研究兴趣**：弹出编辑表单，修改后立即生效（持久化到 `settings.json`）

也可直接发送文本指令：
- `获取日报` / `获取论文` / `日报`：立即获取
- `订阅` / `订阅推送` / `订阅每日推送`：订阅定时推送
- `取消订阅`：取消订阅
- `退出`：返回主菜单

### 定时推送

在 `config/paper_daily.yaml` 中配置 `schedule_time`（北京时间），插件会在每个工作日指定时间自动向所有订阅用户推送论文日报。周末（周六/周日）ArXiv 不发布新论文，自动跳过推送；周一会自动扩展查询范围覆盖周五的论文。

## 配置说明

配置文件：`config/paper_daily.yaml`（参考 `config/paper_daily.yaml.example`）

```yaml
# 用自然语言描述你的研究兴趣，LLM 会据此判断论文相关性
research_interest: |
  我的研究方向是大语言模型的高效推理和部署。
  具体关注：长上下文场景下的 KV Cache 压缩与管理、
  稀疏注意力/线性注意力机制、模型推理加速。
  同时关注 AI Agent 的记忆系统设计（尤其是长期记忆的
  存储与检索机制）、多 Agent 协作架构。
  不太关注：纯理论证明、传统 NLP 任务（NER/文本分类等）、
  语音/图像等非文本模态。

# ArXiv 分类过滤（获取论文时的初筛）
categories:
  - "cs.CL"  # Computation and Language
  - "cs.AI"  # Artificial Intelligence
  - "cs.LG"  # Machine Learning

# LLM 处理的最大论文数（从 ArXiv 获取后截取前 N 篇）
max_papers: 500

# Gemini API 配置（使用 /v1beta/ 端点，无客户端检测限制）
llm_base_url: "https://api.lingyaai.cn"
llm_api_key: "your_gemini_api_key_here"
llm_model: "gemini-3.1-pro-preview-thinking"

# 每日定时推送时间（北京时间 HH:MM 格式）
schedule_time: "09:00"
```

### 配置字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `research_interest` | 字符串 | 用自然语言描述研究兴趣，可包含：关注的方向、具体技术、不感兴趣的方向等。LLM 会根据此描述判断论文相关性并给出推荐理由。也可在飞书中通过「修改研究兴趣」按钮在线编辑，在线修改的值优先于配置文件，持久化在 `settings.json` 中。 |
| `categories` | 列表 | ArXiv 分类代码，用于初筛论文。常用分类：`cs.CL`（计算与语言）、`cs.AI`（人工智能）、`cs.LG`（机器学习）、`cs.CV`（计算机视觉）等。 |
| `max_papers` | 整数 | 从 ArXiv 获取的论文数量上限。建议 200-500，过大会增加处理时间和 API 成本。 |
| `llm_base_url` | 字符串 | Gemini API 基础 URL（需支持 `/v1beta/models/{model}:generateContent` 端点）。 |
| `llm_api_key` | 字符串 | Gemini API Key。 |
| `llm_model` | 字符串 | Gemini 模型名称，推荐 `gemini-3.1-pro-preview-thinking`（带思考链的版本，筛选更准确）。 |
| `schedule_time` | 字符串 | 每日定时推送时间，格式 `HH:MM`（24 小时制，北京时间）。 |

## 工作流程

1. **获取论文**：从 ArXiv 获取昨天发布的论文，按配置的 `categories` 过滤。周六/周日/周一自动扩展查询范围至上周五，覆盖 ArXiv 不发布论文的周末时段
2. **批量筛选**：每 10 篇论文为一批，调用 Gemini API 判断相关性，返回推荐度（1-5 分）和推荐理由
3. **生成摘要**：对推荐的论文（score ≥ 3）逐篇生成 150 字以内的中文摘要
4. **标签归类**：摘要生成后，将所有推荐论文的标题、推荐理由和摘要一次性发给 LLM，统一分配研究方向标签。优先复用已有标签词表中的标签，必要时新增
5. **结果推送**：以飞书卡片形式平铺展示推荐论文，每篇附带标签

## 技术实现

### 架构设计

```
paper_daily/
├── __init__.py              # 插件入口
├── paper_daily_plugin.py    # 主插件类（生命周期、消息处理、卡片构建）
├── config.py                # 配置数据类
├── models.py                # Paper 数据模型
├── fetcher.py               # ArXiv 论文获取
├── gemini_client.py         # Gemini API 客户端（独立模块）
├── processor.py             # 批量筛选 + 摘要生成 + 标签归类 + 缓存管理
├── backfill.py              # 历史回溯脚本（独立运行，按指定日期获取论文）
├── cache/                   # 按日期缓存筛选、摘要和标签结果
│   └── YYYY-MM-DD/
│       └── papers.json
├── tags.json                # 标签词表（跨天复用，自动积累）
├── settings.json            # 用户在线修改的设置（研究兴趣等）
└── subscribers.json         # 订阅用户列表
```

### 核心模块

#### `models.py`
- **Paper 数据类**：定义论文的基础字段（标题、作者、摘要等）、筛选字段、摘要字段和标签字段（`tags: list[str]`）

#### `fetcher.py`
- **fetch_papers()**：使用 `arxiv` 库获取指定日期的论文，按分类过滤并去重。周六/周日/周一自动将查询起点扩展到上周五

#### `gemini_client.py`
- **call_gemini()**：Gemini API 客户端，使用 `/v1beta/models/{model}:generateContent` 端点（无客户端检测限制），支持重试和超时控制
- **GeminiError**：API 调用异常类

#### `processor.py`
- **批量筛选**：每批 10 篇论文，LLM 返回 JSON 数组，包含推荐度和推荐理由
- **摘要生成**：对推荐论文逐篇生成中文摘要
- **标签归类**：摘要生成后，一次 LLM 调用为所有推荐论文统一打标签。基于论文标题、推荐理由和中文摘要进行归类，优先复用已有标签词表
- **标签词表管理**：`tags.json` 存储所有已知标签，每次归类后自动合并新标签，去重排序
- **缓存机制**：按日期缓存筛选、摘要和标签结果（`cache/YYYY-MM-DD/papers.json`），支持断点续跑
- **自动清理**：每次运行时自动清理 180 天前的过期缓存

#### `paper_daily_plugin.py`
- **生命周期管理**：注册时启动定时调度器（守护线程）
- **消息处理**：处理用户文本指令和卡片按钮点击
- **流水线编排**：后台线程执行完整流程（获取 → 筛选 → 摘要 → 标签 → 推送），实时更新进度卡片
- **订阅管理**：持久化订阅用户列表（`subscribers.json`），定时推送时遍历所有订阅者
- **时区处理**：自动将北京时间转换为 UTC 时间进行调度

### 标签系统

**设计目标**：为后续收藏夹功能做预处理，在每日筛选时自动为论文打上标签。

**标签定义规范**：
- 每个标签 2-8 个中文字符，简洁且有代表性
- 标签间语义不重叠，粒度适中（不过粗也不过细）
- 每篇论文可分配多个标签，涵盖其涉及的所有相关方向
- 优先复用已有标签词表中的标签，避免同义标签增生

**标签词表** `tags.json`：
```json
{
  "tags": ["KV Cache 优化", "推理加速", "Agent 架构", "注意力机制", ...]
}
```
- 每次标签归类后自动更新，新增标签追加到列表
- 去重、按字典序排列，便于人工审阅

**标签归类时机**：放在摘要生成之后，因为 LLM 可以利用中文摘要（150 字精炼总结）来更准确地判断论文方向，比仅靠标题和推荐理由信息更充分。

### 缓存机制

按日期缓存筛选、摘要和标签结果（`cache/YYYY-MM-DD/papers.json`），格式：
```json
{
  "2406.12345": {
    "filter": {
      "is_recommended": true,
      "relevance_score": 4,
      "relevance_reason": "提出新的动态淘汰策略"
    },
    "summary": "本文提出了一种基于注意力分数的 KV Cache 动态淘汰策略...",
    "tags": ["KV Cache 优化", "推理加速"]
  }
}
```

**优势**：
- 重复运行时自动跳过已处理的论文，节省 API 调用
- 支持断点续跑：筛选失败时不影响已缓存的结果
- 只在成功时写缓存，避免失败结果污染缓存

## 使用示例

### 1. 配置插件

复制配置模板并填写 API Key：
```bash
cp config/paper_daily.yaml.example config/paper_daily.yaml
vim config/paper_daily.yaml  # 填写 llm_api_key 和 research_interest
```

### 2. 手动获取日报

在飞书中发送 `论文日报`，点击「获取今日日报」按钮，插件会：
1. 从 ArXiv 获取论文（工作日获取昨天的，周末/周一自动扩展到上周五）
2. 使用 Gemini AI 批量筛选（每批 10 篇）
3. 对推荐论文生成中文摘要
4. 统一为推荐论文打标签
5. 以飞书卡片形式平铺展示结果，每篇附带标签

### 3. 订阅定时推送

在飞书中发送 `论文日报`，点击「订阅每日推送」按钮，插件会在每天配置的时间（如 09:00）自动推送论文日报。

### 4. 查看结果

推送的飞书卡片包含：
- **标题行**：日期、筛选总数、推荐数
- **论文详情**：标题（链接到 ArXiv）、作者、推荐度（★★★★☆）、推荐理由、标签、中文摘要
- 最多展示 20 篇推荐论文

## 常见问题

### Q1: 为什么使用 Gemini 而不是 Claude？

A: Gemini API 的 `/v1beta/` 端点无客户端检测限制，可在 Claude Code 环境中正常调用。Claude API 在某些环境下可能被 Anthropic 的客户端检测拦截（302 → app-unavailable-in-region）。

### Q2: 如何调整筛选严格度？

A: 在 `research_interest` 中明确描述"不感兴趣的方向"，LLM 会据此过滤无关论文。也可以修改 `processor.py` 中的 `_BATCH_FILTER_PROMPT`，调整 score 阈值（默认 ≥ 3 推荐）。

### Q3: 缓存会无限累积吗？

A: 不会。插件已实现自动清理机制，每次运行 `process_papers()` 时会自动删除 180 天前的过期缓存。可通过修改 `processor.py` 中的 `CACHE_RETENTION_DAYS` 常量调整保留天数。

### Q4: 定时推送的时区如何处理？

A: 配置文件中的 `schedule_time` 为北京时间（UTC+8）。插件会自动将北京时间转换为 UTC 时间进行调度，无需手动配置服务器时区。例如，配置 `09:00` 表示北京时间早上 9 点推送，插件会自动转换为 UTC 01:00 进行调度。

### Q5: 标签词表如何管理？

A: 标签词表存储在 `tags.json` 中，每次标签归类后自动更新。LLM 会优先复用词表中的已有标签，仅在需要时新增。词表去重、按字典序排列，也可以手动编辑删除不合适的标签。

## 依赖项

- `arxiv`：ArXiv API 客户端
- `httpx`：HTTP 客户端（用于调用 Gemini API）
- `schedule`：定时任务调度

安装依赖：
```bash
pip install arxiv httpx schedule
```

## 注意事项

1. **API 成本**：`max_papers` 设置过大会增加 API 调用次数和成本。建议根据实际需求调整（200-500 篇较合理）。
2. **处理时间**：批量筛选 500 篇论文约需 5-10 分钟（取决于 API 响应速度），用户需耐心等待。
3. **缓存管理**：缓存按日期分目录，自动清理 180 天前的过期缓存，无需手动维护。
4. **时区配置**：定时推送自动处理时区转换，配置文件中使用北京时间即可。
5. **错误处理**：插件已实现重试机制（5xx/429 错误），但网络异常或 API 配额耗尽时仍可能失败。
6. **周末处理**：ArXiv 周末不发布新论文，定时推送在周末自动跳过。周一的推送会自动将查询范围扩展到上周五，确保不遗漏。
7. **标签容错**：标签归类失败不影响日报推送，论文仍可无标签展示。
